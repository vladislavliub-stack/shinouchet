# ШиноУчёт — общий журнал

Рабочий адрес: https://shinouchet.vercel.app

Вход: Vlad / OlgaAnat, пароли заданы владельцем в Supabase. В приложении вводится только логин. Соответствие логинов адресам Supabase находится в закрытой production-переменной Vercel `SHINOUCHET_LOGIN_EMAILS`. Адресов и паролей в клиентском коде нет.

## Возможности

- Микрофон: первое нажатие начинает запись, второе останавливает; карточка открывается после обработки. Groq Whisper Large V3 распознаёт русскую речь. Есть текстовый ввод.
- Госномер, несколько отдельных работ, заметка, редактируемое время и «Шины в утиль». «Константин 565 Ольга Ольга» → «К 565 ОО».
- Общий журнал обновляется каждые 15 секунд при открытом приложении, при возвращении и по кнопке ↻.
- Утиль: ожидает → второй пользователь выбирает ✅ или ❌, может добавить комментарий. Автор не может согласовать собственную запись. Любое изменение содержимого сбрасывает решение и требует проверки.
- Только автор редактирует, удаляет и восстанавливает свою запись. Удаление — в корзину. Аудит хранит автора, время, старые/новые значения и решения.
- Поиск по номеру, история визитов по кнопке, Excel без ID: работы, операции, история, авторы и решения. Корзина не экспортируется.
- Фото и справочника машин нет. Демоданные в общий журнал не добавляются.

## Данные и доступ

Supabase project `wiuuthuxeqrufcewumey`, Free. Доступ только двум разрешённым UUID. RLS включён. Прямые изменения таблиц запрещены. Функции проверяют пользователя, автора и версию строки. Анонимный ключ и посторонний аккаунт не дают доступа к журналу.

Сервер использует publishable key и токен текущего пользователя, без service-role/secret key. Пароли проверяет Supabase Auth. Сеанс хранится в Secure HttpOnly SameSite cookies, не в localStorage. Все API исключены из кеша; распознавание тоже требует входа. `GROQ_API_KEY` остаётся на сервере.

Черновики сохраняются на телефоне отдельно для каждого пользователя. Для входа, журнала, отправки записей и речи нужен интернет. Офлайн доступна оболочка PWA. Сетевая ошибка сохраняет черновик. Конфликт версий не перезаписывает чужое изменение; свежую версию можно открыть с подтверждением.

Старые локальные записи остаются в прежнем хранилище браузера. На исходном телефоне: Excel → «Перенести старые записи». Демо пропускаются; старые изменения отмечаются «Локальный архив» и не могут подделать решение проверяющего. Есть скачивание старого журнала перед переносом. Старые фото в облако не отправляются.

## Разработка

Node.js 20+, внешних пакетов нет.

```sh
node build.mjs
node --test tests/*.test.mjs
node server.mjs
```

Сервер http://localhost:4173 слушает только loopback и обслуживает API. Для реального входа задайте приватно `SHINOUCHET_LOGIN_EMAILS` — JSON с ключами `vlad`, `olgaanat` и адресами соответствующих аккаунтов Supabase; для речи нужен `GROQ_API_KEY`. Не сохраняйте значения в публикуемых файлах. Пароли пользователей не передаются агенту и не хранятся в настройках приложения.

На Vercel нужны серверные функции; статического хостинга недостаточно. `build.mjs` создаёт `dist/`, manifest, иконки и версионный service worker. Неиспользуемые `voice.js`, `local-asr.js`, `asr-worker.js` исключены из развёртывания.

Схема: `supabase/schema.sql`, затем `supabase/import.sql`, `supabase/reviewer-role.sql` и `supabase/comments.sql`. UUID участников привязаны к текущему проекту. `supabase/verify.sql` проверяет реальные правила двух пользователей в транзакции, откатывая все фикстуры.

## Комментарии

Любой участник может оставить комментарий к любой активной записи, без заявки на утиль. Журнал показывает статус «Прокомментировано» и фильтр «Комментарии». Комментарии хранятся отдельно с автором и временем, сохраняются после редактирования и попадают в Excel и историю. Комментарий не меняет решение по утилю. Пустой текст, удалённая запись и устаревшая версия отклоняются сервером.

Обновление существующей базы: `supabase/comments.sql`. Проверка с откатом: `supabase/verify-comments.sql`.
